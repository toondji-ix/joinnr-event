Prepared 19 October 2026. **Status: definition package prepared; approval and phase exit pending.** This implements the review workflow for roadmap phase two, not application features. ## Definition baseline and authority

The [PRD/FRD](01-product.md) owns product scope, stories, personas and metric formulas. [Experience](02-experience.md), [architecture](03-architecture.md), [data](04-data.md), [API](05-api.md) and [matching](06-matching.md) describe the corresponding proposed implementation. The [decision register](08-decisions-and-sources.md) owns policy approval. This package provides traceability and review cases rather than a second product specification. Delivery phase two is not synonymous with EX-02: EX-02 is a technical contract work package, currently covering only three operations.

Confirmed scope: conference-only networking, responsive web and complete native iOS/Android attendee journeys, organizer/planner web administration. Preserve all F-01 through F-18 as P0 release requirements. Deterministic matching precedes semantic integration; this sequence does not remove semantic matching from the MVP. Optional style answers, company, photograph, experience, phone and work URL must not become onboarding prerequisites. Phone implementation remains dependent on D-14. No chat, ticketing, payments, cross-event discovery, scraped profiles or autonomous outreach.

The five personas in document 01 remain hypotheses: first-time engineer, founder, experienced operator, organizer owner and agency planner. Validate each against EX-01 evidence; do not present them as interviewed people. Their journey review must cover manual entry/camera denial, optional style skip, low bandwidth, assistive technology, delegate isolation, consent withdrawal and event closure. Prototype task outcomes belong to EX-03, not this definition review.

## Lifecycle and consent review

Use the state machines in document 01 and integrity rules in document 04. Do not create an alternative state enum in clients. Every operation checks live account, membership, event windows and pair restrictions; a delayed scheduler cannot extend permissions.

| Boundary                              | Required behavior in the proposed baseline                                                                                                           | Review evidence                                                           |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Published but before networking opens | Admission follows its own window; no recommendations or connection actions before networking opens                                                   | At opening minus one instant, at opening, and stale UI request            |
| Admission closes                      | No new admission or rejoin; credentials/intents cannot reserve capacity or extend the window                                                         | At close and duplicate last-seat join                                     |
| Networking closes                     | No recommendations, new requests or grants; pending requests expire; valid existing bilateral contact retrieval remains possible until data expiry   | At close, delayed scheduler, outstanding request and contact read         |
| Cancellation                          | Irreversible; credentials/discovery/new actions disabled; existing contact retrieval and feedback still require live permission and retention checks | Cancel versus join/accept/grant; prior downloaded data cannot be recalled |
| Leave or suspension                   | Remove event visibility and contact access immediately; rejoin resets consent without restoring old grants; suspension needs moderator reinstatement | Leave/rejoin and suspend/contact-read races                               |
| Feedback cutoff                       | Proposed seven days after networking close; private participant responses only; no late edits                                                        | Immediately before and at cutoff; nonresponders remain separate           |
| Event-data expiry                     | Proposed ninety days after networking close; deny reads immediately and purge all applicable stores through privacy lifecycle                        | Expiry while worker or read is in flight; restored-backup erasure         |

Networking consent, optional style processing, semantic processing, contact disclosure and notification preferences are distinct purposes. Acceptance never constitutes contact consent. Grant withdrawal prevents future retrieval; it cannot recall information already disclosed. Style withdrawal invalidates answers and dependent projections without disabling structured recommendations. Semantic processing cannot begin without D-10 terms/consent. No policy is approved by this table: D-04/D-05/D-11 remain open, and exact time-boundary semantics must enter contracts and domain tests before runtime work.

## Measurement review

The eight-family dictionary in document 01 remains authoritative. D-16 review must record metric version, source fact, population/window, numerator, denominator, exclusions, freshness, suppression and actual decider. All thresholds remain proposed.

| Family                 | Required review check                                                                                                                                                                |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Meaningful connections | Count unordered accepted event pairs once with at least one yes by cutoff; show two-sided confirmations separately; divide by activated attendees and show acquisition-to-activation |
| Acceptance             | Recommendation-origin accepted / delivered requests created in networking window; acceptance counted through close; display pending/withdrawn separately                             |
| Profile completion     | Complete required profile and networking consent / admitted active memberships; skip style resolves the optional step                                                                |
| Participation          | Unique admitted members viewing a recommendation or acting on a request / admitted active memberships; never label venue attendance                                                  |
| DAU/MAU                | Intentional active users in day / rolling thirty-day users; segment by event cycle; never count background delivery as intent                                                        |
| Retention              | D1/D7 only for activated users whose event remains open; next-event cohort includes only those invited; display eligible denominator                                                 |
| Referrals              | Newly admitted attributed users; exclude self and duplicate membership; share token does not grant admission                                                                         |
| Satisfaction           | Private 1 to 5 ratings, distribution, respondent count and response denominator; settle weighting of two respondents per connection under D-16                                       |

Zero denominator yields null, not zero percent. Display response coverage and nonresponse uncertainty; do not infer usefulness from acceptance or contacts unlocked. D-16 must settle cohort snapshot rules for departures/suspensions, cancelled events, feedback response denominator, rating weighting and late-arriving events before analytics contracts freeze. Until then, do not invent SQL aggregates or claim that pilot thresholds passed.
